# Card design, SVG motifs, and themes — first pass

**Status:** first pass, awaiting review. Nothing is wired into the app.
**Review sheet:** [`card-design-review.html`](./card-design-review.html) — open it and use the theme switcher.
**Motif sources:** [`motifs/*.svg`](./motifs/)
**Relationship to [`ui-enhance.guide.md`](./ui-enhance.guide.md):** this plan **deliberately overrides** §3 (“at most three merlot roles”, “do not invent a second brand color”) and §10 (“no second accent”, “dark mode is never a different palette”) — approved on the condition that every override is reversible. §6 of this doc is that escape hatch.

## 1. What exists today

| Asset | Reality |
|---|---|
| `src/components/wine-mark.tsx` | The only brand illustration. Filled merlot bottle, four jagged splits, rotated −18°. |
| `public/brand/*` | PNG icons only (favicon, touch icon, OG). No vector motifs. |
| `public/*.svg` | `next.svg`, `vercel.svg`, `globe.svg`, `file.svg`, `window.svg` — all unused Next.js scaffolding. Should be deleted. |
| `react-native-svg` 15.15.4 | Already a dependency in `apps/mobile`. No new native module needed for SVG. |
| `lucide-react` / `lucide-react-native` | Already present for UI icons. Motifs are *not* a lucide job — lucide is for affordances (copy, share, back), motifs are for atmosphere. |

**Nothing was downloaded.** Stock SVG packs carry attribution or share-alike terms that are a nuisance in an App Store binary, and the design guide explicitly rejects “autogenerated illustration clutter.” Every motif here is authored from the `WineMark` vocabulary: the jagged split is the through-line.

## 2. The motif kit (10 files, built)

All files are stroke-only, `viewBox="0 0 48 48"` (except the two noted), and paint with `currentColor` — so a single file serves every theme, light or dark, with no variants.

| File | Reads as | Intended use |
|---|---|---|
| `split-bottle.svg` | The signature | Card chrome next to the wordmark; line-art sibling of `WineMark` |
| `stem.svg` | A single glass | Drink line marker on claim rows |
| `pour.svg` | Stream + pool | The settle moment; the one motif allowed to animate |
| `check-stub.svg` | Itemized bill, torn foot | “The tab” / food line marker |
| `coupe-pair.svg` | Two glasses leaning in | Share / invite kicker |
| `carafe.svg` | The shared pour | Shared or split lines |
| `cork.svg` | Opened, not sealed | “The night started” — host desk, outing cards |
| `label-band.svg` | A wine label as a rule | Venue kicker ornament |
| `grapes.svg` | Abstract cluster | Decorative only. Easiest motif to overuse — cap it. |
| `perforation.svg` | Tear line, ticket notches | Divider between card sections (240×10) |
| `split-wash.svg` | Oversized jagged splits | Card watermark at 3–4% opacity (160×160) |
| `paper-grain.svg` | Linen tooth | Canvas grain, capped at 2–4% per guide §4 |

### Two rules learned while building the review sheet

1. **Never stretch `perforation.svg`.** With `preserveAspectRatio="none"` the ticket notches deform into arrowheads. In-card, use a CSS dashed rule instead; the SVG is for reference and fixed-width use. The review sheet now does exactly this.
2. **The watermark must fade out.** At a flat 5.5% opacity the wash crossed the payment rows and read as a rendering artifact. It needs a `mask-image: linear-gradient(to top, #000, transparent)` and ~3.8% opacity so it dies before it reaches content.

## 3. Themes

Four token sets. Same markup, same copy, same layout — only custom properties change.

| Theme | Paper | Ink | Accent | Honest assessment |
|---|---|---|---|---|
| **linen** *(default)* | `#F6F4F1` | `#2A241C` | `#6E2E35` merlot | Byte-for-byte today's contract. The control. |
| **candlelight** | `#EFE7DC` | `#241C14` | `#7A2630` | Dimmer, warmer. The most defensible override — it is the current palette after dusk, not a new identity. |
| **cellar** | `#171310` | `#F2EBE1` | `#C4566A` | Genuinely handsome dark mode. Caveat: merlot must lift to stay legible on near-black, and at `#C4566A` it reads closer to rosé than merlot. Expect to tune. |
| **patio** | `#FBF9F4` | `#232B26` | `#2F5D50` bottle green | The real break — it swaps the accent. Attractive, but a green CTA is no longer recognizably Split the Wine, and it collides with `select`/`selectWash`, which already mean “claimed.” **Highest rollback risk.** |

Three of the four accents already exist in `apps/mobile/src/lib/theme.ts` (`merlot`, `kindFood` amber for candlelight's wash, `select` green for patio). That is deliberate: the override reuses sanctioned hexes instead of inventing a palette, so reverting is deleting a map entry rather than hunting down stray colors.

### Where a theme is chosen

- Host picks at publish time (or from the share screen).
- Stored on the receipt/outing so guests inherit it — the claim link carries the host's choice.
- Guests never pick; a per-guest theme would make screenshots inconsistent at one table.

## 4. Architecture

```
src/lib/card-theme/
  themes.ts        token maps, keyed by theme id; `linen` is the default export
  resolve.ts       pick a theme from receipt.themeId, fall back to linen
src/components/motifs/
  index.tsx        <Motif name="stem" />, tree-shakeable
apps/mobile/src/components/motifs/
  index.tsx        same names, react-native-svg primitives
```

Web consumes tokens as CSS custom properties on a wrapper (`data-card-theme="candlelight"`), so no component reads a hex directly. Native consumes the same map as a plain object through the existing `colors` import site, which means `theme.ts` becomes `themes.linen` and every current call site keeps working.

Motif components accept only `name`, `size`, and `className`/`style`. They never set color — `currentColor` inherits it. One file, every theme.

## 5. Three.js — where it earns its place

Honest read: **the card work does not need WebGL, and v1 should not ship it on the claim path.** What makes these cards feel designed is the motif kit, the tear line, the watermark, and type hierarchy — all of which are crisp, instant, and free. Three.js buys one thing: a liquid pour that genuinely moves.

| Surface | Verdict | Reasoning |
|---|---|---|
| Marketing hero (`marketing/`) | **Yes** | Desktop, no battery pressure, no one waiting to split a check. The right place for a real scene. |
| Settle “You owe” | **Maybe — one pour** | A single ~1.5s liquid fill in the theme accent, behind the amount. Needs a static `pour.svg` fallback and a `prefers-reduced-motion` off-ramp. |
| Share card | **Not v1** | The win is a crisp, screenshot-worthy SVG card. WebGL adds bundle and first-paint cost exactly when the host is rushing to send a link. |
| Claim rows | **No** | Scroll performance and thumb latency at a dim table. 2D permanently. |
| Native (Expo) | **Defer** | `@react-three/fiber` on React Native needs `expo-gl` plus native modules, which breaks the Expo-Go-compatible constraint in `apps/mobile/README.md`. Web first; native only if the web pour proves its worth. |

Constraints if it ships: at most one canvas on screen, pause offscreen, cap DPR, no shadow maps, SVG chrome and all text composited **above** the canvas so type is never WebGL-rendered.

## 6. Rollback

Every step below is independent — you can reverse one without touching the others.

| If you hate… | Do this | Blast radius |
|---|---|---|
| One theme | Delete its entry from `themes.ts` | None. Resolve falls back to `linen`. |
| All alternates | Set the default to `linen`, drop the picker | Pixel-identical to today. |
| The motifs | `<Motif>` returns `null` behind one flag | None. No layout reserves motif space, so nothing reflows. |
| The watermark / grain | Remove the `.wash` element or set opacity to 0 | None. Purely decorative, absolutely positioned. |
| The 3D | Delete the lazy import | Falls back to the static `pour.svg` it was already layered over. |

The load-bearing decision is keeping `linen` byte-identical to the shipped palette. As long as that holds, “too ugly” is always one-line reversible.

## 8. Open questions

1. **Patio** is the one I would cut — a green CTA reads as a different product and it fights the existing `select` green. Keep it as a swatch, or drop it now?
2. **Cellar** needs its accent tuned; `#C4566A` is more rosé than merlot. Want me to iterate on that hex, or is dark mode out of scope until later?
3. Is `candlelight` worth shipping as a *manual* theme at all, or should it be an **automatic** dusk variant (time-of-day), which is arguably the better product?
4. Settle pour: build it in Phase 2 as proof, or leave Three.js entirely to the marketing site?
